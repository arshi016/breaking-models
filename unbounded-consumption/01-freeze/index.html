What just happened?

Filter v1 uses the regex ^(\w+\s?)*$, which means "words, each with an optional space after it". Your prompt ends with !, so the honest answer is no. But before the engine says no, it tries every way to split your letters into words, in case one of them works.

aaaa has 3 gaps between letters. At each gap the engine can split or not split, so it has 2 × 2 × 2 = 8 ways:

With n letters it has 2n−1 ways. 28 letters means 134,217,728 ways, and every extra letter doubles the work.

The fix is ^[\w\s]*$: one flat set of allowed characters, read once from left to right, so it answers instantly. This bug class is ReDoS (CWE-1333). It happens in backtracking regex engines (JavaScript, Python, Java, PCRE). RE2-style engines (Go, Rust) do not backtrack.
